# Story 01 — Set up Laravel project, MySQL, env config and repo structure (Story: KAN-14)

## Prerequisites

- None. This is the first story of epic **KAN-4 Project foundation**.
- Local MySQL **8.4.10** (Laragon) reachable at `127.0.0.1:3306`, user `root`, empty password. Verified during planning.
- PHP **8.4** with `pdo_mysql` enabled. Verified during planning.
- The base Laravel app **already exists** at the project root (Laravel **v13.38.0**, Filament **v5.10.3**, Inertia v3 + React, Fortify, Pest 5). **Do not** run `laravel new` or `composer create-project`. This story turns the existing app into the baseline repo.

---

## Story Goal

Turn the existing Laravel skeleton into the agreed project baseline:

1. The project is a **Git repository** with one initial commit on `main`, and no secrets in it. That commit is **pushed** to GitHub at `https://github.com/7at7ot777/Spec-Drivien-Development-Project`.
2. Local development runs on **MySQL** (database `sdd_project`), not SQLite.
3. `.env.example` documents **every** variable the app needs: app, DB, mail, SMS, Fawry and media storage. Each new group has a short comment.
4. `config/services.php` exposes the **SMS** and **Fawry** variables so later stories read them through `config()`, never `env()`.
5. A root **`README.md`** explains local setup and the **folder conventions**.
6. `php artisan migrate:fresh` runs cleanly on an empty MySQL database and the app serves `/`.

**Out of scope** (covered by sibling KAN-4 / later stories, do **not** start them here):
- Sanctum, `/api/v1`, JSON response envelope and error handling: **KAN-15**.
- Localization (ar/en): **KAN-16**.
- Filament panel provider and operations login: **KAN-17**. Filament is installed but **no** panel provider is registered in `bootstrap/providers.php`. Leave it that way.
- CI pipeline changes: **KAN-19**. Do not edit `.github/workflows/tests.yml`.
- Media disk and signed URLs: **KAN-35**. Payment gateway driver code: **KAN-37**. SMS/email notification channels: **KAN-55**. This story only adds the **env variables and config keys** for these. It adds **no** driver classes.

### 7 — Unit test for env documentation

**Create file: `tests/Unit/EnvironmentExampleTest.php`** with `php artisan make:test --pest --unit EnvironmentExampleTest --no-interaction`, then replace its body with this (match `tests/Unit/ExampleTest.php` style):

```php
<?php

/**
 * @return array<string, string>
 */
function envExampleValues(): array
{
    $values = [];

    foreach (file(dirname(__DIR__, 2).'/.env.example', FILE_IGNORE_NEW_LINES | FILE_SKIP_EMPTY_LINES) as $line) {
        if (str_starts_with(ltrim($line), '#') || ! str_contains($line, '=')) {
            continue;
        }

        [$key, $value] = explode('=', $line, 2);
        $values[trim($key)] = trim($value);
    }

    return $values;
}

test('env example documents every required variable', function (string $key) {
    expect(envExampleValues())->toHaveKey($key);
})->with([
    'DB_CONNECTION', 'DB_HOST', 'DB_PORT', 'DB_DATABASE', 'DB_USERNAME', 'DB_PASSWORD',
    'MAIL_MAILER', 'MAIL_HOST', 'MAIL_PORT', 'MAIL_USERNAME', 'MAIL_PASSWORD', 'MAIL_FROM_ADDRESS',
    'SMS_DRIVER', 'SMS_API_URL', 'SMS_API_KEY', 'SMS_SENDER_ID',
    'FAWRY_BASE_URL', 'FAWRY_MERCHANT_CODE', 'FAWRY_SECURITY_KEY', 'FAWRY_CALLBACK_URL',
    'FILESYSTEM_DISK', 'MEDIA_DISK', 'MEDIA_MAX_VIDEO_MB', 'MEDIA_SIGNED_URL_TTL_MINUTES',
]);

test('env example defaults to mysql', function () {
    expect(envExampleValues()['DB_CONNECTION'])->toBe('mysql');
});

test('env example leaves secrets empty', function (string $key) {
    expect(envExampleValues()[$key])->toBe('');
})->with(['DB_PASSWORD', 'SMS_API_KEY', 'FAWRY_MERCHANT_CODE', 'FAWRY_SECURITY_KEY', 'AWS_SECRET_ACCESS_KEY']);
```

Unit tests do **not** boot the app (`tests/Pest.php` lines 17–19 extend `TestCase` for `Feature` only), so `base_path()` is unavailable. The path is built with `dirname(__DIR__, 2)` for that reason. **Do not** swap it for `base_path()`.

## Edge Cases & Failure Modes

- **MySQL not running or wrong credentials.** `migrate:fresh` fails with `SQLSTATE[HY000] [2002]` or `[1045]`. Expected: the README "Local setup" step tells the developer to edit `DB_*` in `.env`. No code handles this; `config/database.php` lines 47–66 read env only.
- **Database missing.** `SQLSTATE[HY000] [1049] Unknown database 'sdd_project'`. Fixed by task 1. The README includes the `CREATE DATABASE` line.
- **Charset mismatch.** If the database is created without `utf8mb4`, Arabic text (KAN-16) breaks later. Task 1 pins `utf8mb4_unicode_ci` to match `config/database.php` lines 56–57.
- **Stale config cache.** If `bootstrap/cache/config.php` exists, env changes are ignored. Task 4 runs `php artisan config:clear` first.
- **Tests accidentally hit MySQL.** `phpunit.xml` lines 26–27 force in-memory SQLite. **Do not** remove them. MySQL-only SQL in future migrations, such as `ENUM` changes or fulltext indexes, will not be caught by tests. This is a known gap; KAN-19 decides whether CI adds a MySQL service.
- **`composer setup` on a fresh clone runs `migrate --force`.** That fails if MySQL or the database does not exist yet. The README orders `CREATE DATABASE` **before** `composer setup`.
- **`post-create-project-cmd` touches `database/database.sqlite`.** That's harmless: it only runs on `create-project`, and `database/.gitignore` ignores `*.sqlite*`.
- **Env interpolation.** `SMS_SENDER_ID="${APP_NAME}"` and `FAWRY_CALLBACK_URL="${APP_URL}/..."` need double quotes. `APP_NAME="SDD Project"` contains a space and must be quoted, or `.env` parsing fails at boot. The unit test parser in task 7 treats the quoted value as a raw string, which is fine for the key and empty-secret checks.
- **Secrets committed.** `.env` (`.gitignore` line 15) and `.squad/secrets.yaml` (line 48) are ignored. Task 10's guard checks this before the first commit. The Jira API token in `.squad/secrets.yaml` must **never** be staged.
- **Agent files not shared.** `.gitignore` lines 32 and 40–43 ignore `/.claude`, `/.mcp.json`, `/AGENTS.md` and `/boost.json`, so the squad-kit slash commands in `.claude/commands/` are **not** committed. This is intentional (Boost regenerates them). The README Workflow section tells each developer to run `squad init` / `php artisan boost:install` locally. **Do not** edit `.gitignore` in this story.
- **`SMS_DRIVER` exported in the developer shell.** `ServicesConfigTest` "sms driver defaults to log" fails. To fix, add `<env name="SMS_DRIVER" value="log"/>` to `phpunit.xml` after line 34. Do this only if the failure actually occurs.
- **Push rejected (`! [rejected] main -> main (fetch first)`).** Someone pushed to the remote after planning. Expected: stop and ask the user. **No** force push (task 11).
- **Push auth fails (`403` / `Authentication failed`).** The developer's GitHub account lacks write access to `7at7ot777/Spec-Drivien-Development-Project`. Expected: report it. The local commit stays intact and the push can be retried after access is granted.
- **Secrets on GitHub.** Pushing a secret makes it public, even if it's removed later. The task 10 guard **must** pass before task 11. If a secret is pushed, rotate it immediately: the Jira API token at id.atlassian.com, and any value from `.env`.
- **Fawry sandbox URL.** `https://atfawry.fawrystaging.com` is used as the documented default. KAN-42 confirms it against Fawry's current sandbox docs, and it can change there without code edits.
